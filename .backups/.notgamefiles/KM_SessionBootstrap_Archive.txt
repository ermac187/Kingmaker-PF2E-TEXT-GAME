---------------------

=============================================================

ATOMIC FILE CONVENTION (post-refactor standard)
=============================================================

Naming:    KM_<scope>_<NN>_<slug>.md
           Pre-Prologue: KM_PP_01_arrival.md … KM_PP_09_restov_walk.md
           Prologue:     KM_PR_01_manor_arrival.md …
           Chapter N:    KM_C<N>_NN_<slug>.md

Hard limit: ≤ 8 KB per atomic file. NEVER exceed. If a beat is bigger
than 8 KB it should be split into sub-beats.

Required header in every atomic file (5-line DO-NOT block at top):
  > ⛔ DO NOT  (1) advance scene without listed exit trigger
  > ⛔ DO NOT  (2) speak/move for the player
  > ⛔ DO NOT  (3) invent NPCs, locations, or rules absent here
  > ⛔ DO NOT  (4) skip required outputs at end of beat
  > ⛔ DO NOT  (5) load a different beat file mid-response

Required sections in every atomic file:
  - STATE IO contract: what fields are read from save_block, what
    fields are written, what transitions exit this beat
  - REQUIRED OUTPUTS: 3–5 things every response in this beat must show
  - OPENING NARRATION (verbatim if scripted, framework if reactive)
  - PLAYER MENU (10–30 options) or "free input" with action handler
  - EXIT TRIGGERS: explicit conditions that move state to the next beat

Pair-load: atomic files do NOT pair-load. One file per beat. Lookup
files (stat blocks, build maps, XP tables) are referenced by pointer,
loaded only when needed.

           → NPC responds.
